# Train E — E3.4 Multi-user Lifecycle

## Scope

E3.4 adds revision-safe progress tracking for every reserved exchange leg after E3.3 activation.

## Contract

- the sending participant confirms dispatch for their own leg;
- the receiving participant confirms receipt only after sender confirmation;
- duplicate confirmations are idempotent;
- stale revisions are rejected;
- outsiders and the wrong participant cannot advance a leg;
- disputed or cancelled legs cannot progress;
- the exchange completes only when every leg is fulfilled;
- completion is atomic and blocked by any disputed or cancelled leg.

## State flow

`reserved → sender_confirmed → fulfilled`

`reserved|sender_confirmed → disputed|cancelled` is reserved for E3.5 authority.

## Safety boundary

E3.4 does not add ownership transfer, notifications, rewards, reputation changes, stories, direct browser table writes or automatic Production migration application.

## Evidence

- pure TypeScript lifecycle aggregation and actor-authority tests;
- migration contract tests;
- existing CI, AI regression gate, Build and Vercel Preview.
