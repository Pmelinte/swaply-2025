# Train E / E4.1 — Commercial Contract & Existing Monetization Inventory

## Scope

E4.1 defines the canonical commercial boundary for Swaply before any new payment or provider integration is activated.

The exchange itself remains free. Swaply may monetise optional connected services, transparent affiliate recommendations and clearly marked promoted visibility. Commercial features must never alter trust rank, exchange authority or participant rights.

## Repository inventory found before E4.1

The repository already contains legacy or partial implementations for:

- Stripe configuration and payment helpers;
- subscriptions with `free`, `premium` and `platinum` plan identifiers;
- featured listings and boost UI;
- swap insurance records;
- seasonal promotions;
- referral and token reward mechanisms;
- item auctions and token bids;
- an escrow migration;
- monetisation and integration pages.

Their presence in the repository does not mean they are approved for Production use.

## Canonical classification

### Keep

- optional third-party logistics;
- optional packaging services;
- transparent affiliate offers.

### Sandbox only

- third-party insurance;
- paid featured visibility;
- payments for connected services.

These require explicit activation gates and must remain separate from the core exchange.

### Defer

- premium subscriptions until benefits and billing promises are canonical;
- item auctions;
- token marketplace, gifts or money-like token utility.

### Prohibited for v1

- Swaply-held escrow;
- Swaply wallet or stored monetary value;
- Swaply credit or lending.

## Mandatory guardrails

1. The core exchange is not charged.
2. Trust rank cannot be bought or improved through payment.
3. Sponsored, promoted and affiliate content is visibly disclosed.
4. External-provider failure cannot block the core exchange.
5. Swaply does not store card data.
6. Production payments require explicit activation after webhook, refund and reconciliation gates.
7. Existing legacy code is not treated as active commercial authority.

## Explicit non-scope

E4.1 does not:

- create or apply a database migration;
- activate Stripe or any payment provider;
- create checkout, webhook or refund flows;
- enable subscriptions, paid boosts, auctions, insurance or escrow;
- modify trust, ranking, matching or exchange lifecycle;
- introduce prices or fees.

## Gate

E4.1 is complete when the commercial contract and inventory validator are merged with full CI and Vercel Preview green. Production activation of any classified mechanism requires a later E4 batch and Petru's explicit approval.
