# Train E / E4.2 — Provider Registry & Integration Layer

## Scope

E4.2 introduces a common, server-oriented contract for external commercial providers without activating any Production integration.

## Implemented

- canonical provider registry;
- capability declarations for payments, courier, packaging, insurance, travel, accommodation and affiliate services;
- explicit `sandbox` / `production` environment boundary;
- disabled-by-default canonical providers;
- secret names declared as server environment variables only;
- bounded timeout and retry policies;
- circuit-breaker policy and state contract;
- deterministic fallback results;
- provider failure cannot block the core exchange;
- validation that rejects unapproved Production activation;
- unit coverage for disabled providers, retry, circuit opening and capability selection.

## Initial canonical entries

- Stripe — payments, sandbox, disabled;
- generic courier integration — courier, sandbox, disabled;
- Booking affiliate — accommodation and affiliate, sandbox, disabled.

These entries describe integration contracts only. They do not prove credentials, provider approval, legal readiness or live connectivity.

## Safety boundaries

- no provider is enabled;
- no secret value is stored in source code;
- no API route is migrated in this batch;
- no payment, checkout, webhook, AWB, booking or affiliate conversion is created;
- no database migration is added;
- no Production provider is activated;
- external failure always returns a non-blocking fallback for the core swap.

## Gate

E4.2 is complete when registry validation, provider executor tests, full CI, AI regression gate and Vercel Preview are green. Merge still requires Petru's explicit command.
