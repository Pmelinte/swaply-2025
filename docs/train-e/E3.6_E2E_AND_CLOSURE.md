# Train E / E3.6 — E2E & Closure

## Scope

E3.6 defines the terminal evidence gate for the E3 multi-user exchange programme. It does not add new business behaviour; it verifies that E3.1–E3.5 form one coherent, server-authoritative system.

## Canonical matrix

1. three-participant circular completion;
2. bundle activation with unanimous consent on one revision;
3. participant refusal with zero partial activation effects;
4. stale-revision rejection across concurrent sessions;
5. duplicate confirmation idempotency;
6. cancel-versus-completion race with one authoritative terminal result;
7. leg dispute blocking completion;
8. authenticated outsider with zero read or mutation authority;
9. reload/reconnect stability;
10. cleanup strictly by captured immutable identifiers.

Every scenario requires at least three authenticated actors. The outsider case uses a fourth authenticated actor. Concurrency scenarios require independent sessions.

## Closure invariants

- bilateral exchanges remain compatible;
- all multi-user writes remain server-side RPC operations;
- one participant cannot accept or confirm for another;
- stale revisions have zero side effects;
- activation is atomic;
- completion requires every leg to be fulfilled;
- disputes block completion and downstream rewards;
- cancellation releases only active reservations;
- consumed reservation evidence is immutable;
- replay and double click are idempotent;
- outsider access remains denied;
- test cleanup uses immutable IDs, never mutable labels or broad predicates.

## Evidence policy

The milestone is not emitted when evidence is missing, failed or outside the canonical matrix. The terminal milestone is:

`ADVANCED_MULTI_USER_EXCHANGE_READY`

## Operational boundary

Repository tests validate the contract and migration chain. Applying migrations to Supabase Production and running authenticated Production fixtures remain explicit operational actions; a Vercel deployment alone does not prove database migration parity.

## Closure decision

E3 may be declared closed only after:

- the E3.6 PR is green and merged;
- Vercel Production is Ready;
- the E3 migration chain is verified as applied in Supabase Production;
- authenticated runtime evidence for the canonical matrix is retained;
- cleanup is confirmed with zero fixture residue.
