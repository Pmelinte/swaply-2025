# V1-09.5 — Legal reconciliation

**Status:** REMEDIATION IMPLEMENTED / CI PENDING  
**Baseline SHA:** `9c36808fb4b43e146a4aef27a5e62402b2d45475`  
**Package:** `V1-09 — ACTIVE / PARTIAL`

## Purpose

Reconcile public Terms with the current Swaply product and verified runtime behavior without inventing inactive capabilities or weakening existing safety/privacy controls.

## Confirmed mismatches on baseline

1. Terms stated that all private messages were automatically moderated for profanity, personal-data leaks and spam. Repository inspection did not prove universal pre-delivery message moderation.
2. Terms described Swaply as an object-only exchange platform, while the current product has four domains: Objects, Properties, Services and Events.
3. Terms stated that a user could simply delete the account at any time, while the current authority routes deletion through the GDPR deletion workflow with deletion/anonymisation/justified retention semantics.
4. Terms used a February 2026 revision date although Privacy/Legal behavior changed materially during V1-09.
5. Prohibited-content language required reconciliation so that platform rules remain explicit without falsely implying automatic enforcement.

## Remediation

### Runtime authoritative Terms copy

`src/lib/legal-copy.ts` now provides narrowly scoped authoritative overrides for materially stale Terms sections:

- account rules;
- swap rules;
- prohibited content/transactions;
- moderation and safety tools;
- limitation of liability.

Historical translated strings remain the fallback for sections that are not materially stale. Existing public-domain normalization remains unchanged.

### Account rules

Public Terms now state that account deletion uses the GDPR deletion workflow and that records can be deleted, anonymized or retained where justified for security, disputes, fraud prevention, accounting or legal obligations.

### Product scope

Public Terms now cover Objects, Properties, Services and Events instead of object-only exchanges.

### Prohibited rules

Public Terms continue to prohibit illegal goods/services/activities/transactions, including weapons, illegal drugs, counterfeit goods, stolen property and hazardous materials. The wording no longer implies automatic enforcement; restriction/removal/reporting/suspension is described as occurring after review.

### Moderation / report / block / dispute

Public Terms now describe the safety capabilities actually evidenced by the product: reporting, blocking and dispute tools. They explicitly avoid promising universal automatic screening or moderation of every private message before delivery.

### Legal revision date

Terms revision date is now `2026-08-08`.

## Regression tests

`src/__tests__/legal-copy.test.ts` now asserts:

- the current Terms revision date;
- absence of the false universal automatic-moderation claim;
- report/block/dispute wording;
- coverage of all four product domains;
- prohibited categories without automatic-enforcement claims;
- GDPR deletion-workflow semantics.

## Explicit non-changes

This unit does not:

- change Supabase schema, RLS or migrations;
- add a new moderation engine;
- change report/block/dispute authority;
- activate payment, escrow, insurance, Premium or Business capabilities;
- change AI providers or AI runtime behavior;
- authorise `v1.0.0`, GitHub Release or `SWAPLY_V1_GA`.
