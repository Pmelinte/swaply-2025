# V1-10.1 — Recovery truth inventory and isolated restore drill

**Package:** `V1-10 — Recovery and operations`  
**Unit:** `V1-10.1`  
**Baseline application SHA:** `3bdcf71a160fdee53280b337e99c31d3e8f3b588`  
**Supabase Production:** `keaejxlwqtjjglijiplh`  
**Mode:** recovery evidence without destructive Production actions

## 1. Purpose

V1-10 must prove that Swaply has a credible recovery path, not merely a deployable application. This unit creates an executable recovery contract and gathers evidence in two separate layers:

1. a read-only Production inventory containing counts only;
2. a deterministic PostgreSQL logical backup and restore drill in an isolated database.

The two layers must never be conflated. The isolated dump contains synthetic data only. The Production inventory exports no rows, user emails, message contents, Story bodies, exact locations, ledger entries or Storage object names.

## 2. Current operational boundary

The Supabase organization is currently on the Free plan. The current Supabase platform documentation does not provide downloadable managed database backups for Free projects and recommends regular logical exports maintained off-site. Therefore V1-10 must not claim that a managed Production backup exists when it has not been demonstrated.

The database and media boundaries are also distinct:

- a PostgreSQL database backup covers database state and Storage metadata;
- it does not recover the actual bytes stored through the Storage API;
- Cloudinary or any other external media provider requires its own inventory and recovery procedure;
- Auth recovery from an application-level REST export does not preserve password hashes and may require password reset unless a true database dump is available.

## 3. Executed evidence in this unit

The workflow `.github/workflows/v1-10-1-recovery-drill.yml` performs:

1. a contract test for every recovery artifact;
2. a read-only Production count inventory using the existing server-side Supabase credential;
3. an isolated PostgreSQL 17 source database with representative Swaply private and public resources;
4. a custom-format `pg_dump` logical backup;
5. a SHA-256 checksum and non-empty backup check;
6. a clean restore through `pg_restore`;
7. validation of data counts, relationships, RLS, policies and deterministic checksums;
8. a transactional rollback test;
9. a forward-fix migration test;
10. 90-day GitHub Actions artifacts containing only synthetic dump data and non-sensitive Production counts.

## 4. Representative recovery fixture

The synthetic fixture covers:

- `auth.users`;
- `storage.buckets` and `storage.objects` metadata;
- profiles;
- items;
- swaps;
- conversations and messages;
- Stories and revision-bound consents;
- the append-only Swapleni ledger;
- Blog translations;
- foreign keys, uniqueness rules, checks, RLS flags and policies.

It intentionally uses only reserved synthetic UUIDs and `example.invalid` addresses.

## 5. Explicit non-claims

V1-10.1 does not claim that:

- the Free-plan Supabase project has a managed downloadable backup;
- Production data rows were exported;
- Production was restored or mutated;
- Storage media bytes were backed up;
- Cloudinary media were backed up;
- an application rollback alias was changed;
- secret rotation was executed;
- V1-10 is closed.

These boundaries are carried into the V1-10 recovery record and operations runbooks. A later V1-10 unit must either execute an acceptable Production logical backup or record the owner-approved operational recovery boundary without inventing stronger evidence.

## 6. Pass criteria

V1-10.1 passes only when:

- CI is green;
- the Production count inventory completes read-only;
- the synthetic backup is non-empty and checksummed;
- the clean restore succeeds;
- every integrity assertion succeeds;
- rollback and forward-fix assertions succeed;
- artifacts are uploaded for the exact PR head;
- Vercel Preview is ready;
- no Supabase Production migration or data write occurs.

## 7. Release boundary

This unit does not authorize `v1.0.0`, GitHub Release, `SWAPLY_V1_GA`, paid AI, payments, escrow or commercial-provider activation.
